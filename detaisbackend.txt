1. CORE ARCHITECTURE & TECHNOLOGY STACK
--------------------------------------------------------------------------------
* Framework: Spring Boot (v2.3.6.RELEASE)
* Platform: Java 8 (fully compatible with standard JVM runtimes)
* Servlet Engine: Tomcat Embedded (Servlet API 3.x - javax.servlet scope)
* Authentication: Stateless JWT-based signature validation (HS256)
* Storage Model: JSON-based atomic flat-file datastore (db.json)
* Thread Safety: ReentrantReadWriteLock (fair locking mechanism on database reads/writes)
* Durability: Multi-version rolling database auto-backups (last 5 historical copies preserved)

  4. ./db.json (Local execution path)
  5. db.json (Default fallback path)

B. Core Database Methods:
  * getList(String key): Performs a shared read-locked lookup for database collections.
  * add(String key, Map<String, Object> item): Adds a new item, automatically generating a 
    unique 8-character ID if none exists, and issues an atomic save request.
  * update(String key, String id, Map<String, Object> updatedItem): Performs a write-locked
    merge (putAll) patch operation on matching IDs and commits changes.
  * delete(String key, String id): Removes matching records safely.
  * save(): Creates a timestamped rolling backup under the parent 'backups/' directory
    (maintaining only the latest 5 files) and then flushes changes to disk.

3. IDENTITY & SECURITY ARCHITECTURE (JWT SPECIFICATION)
--------------------------------------------------------------------------------
The application utilizes a high-security custom JWT (Json Web Token) signature utility 
(JwtUtil.java) to authorize sessions, verify identities, and prevent unauthorized actions.

A. Signature Configurations:
  * Algorithm: HMAC-SHA256 (HS256)
  * Signature Secret: "HomieFurnitureRentalsSuperSecretProductionJWTKey2026"
  * Token Lifespan: 10 Days (240 Hours) from issuance

B. Token Payload Claims Schema:
  {
    "id": "bfa6",                       // User unique identifier
    "role": "admin",                    // Authorization role: "admin" | "user"
    "phone": "9355693923",              // User registered phone number
    "exp": 1781010041700                // Expiration Unix Timestamp (ms)
  }

C. Controller Security Interceptor Logic:
  Protected operations intercept the "Authorization" HTTP Header. If the header starts 
  with "Bearer ", the token signature is checked against the server-secret.
  * If the signature is valid and the token is active, user claims are extracted.
  * Access rights are strictly evaluated:
    - Normal Users: Can ONLY access/modify/delete resources belonging to their own 'id'.
    - Administrators: Can perform any administrative write or read operations globally.

4. COMPLETE REST API ENDPOINT REFERENCE
--------------------------------------------------------------------------------

--------------------------------------------------------------------------------
A. USERS ENDPOINTS (/users)
--------------------------------------------------------------------------------
1. GET /users
   * Description: List all registered user profiles.
   * Access: Admin role can view all. Regular users are strictly limited to their own record.
   * Query Parameters: ?phone=9355693923 (Optional filter by phone number)
   * Headers: Authorization: Bearer <token> (Optional/Enforced for non-admins)
   * Response: 200 OK - Array of user objects.

2. GET /users/{id}
   * Description: Retrieve detailed user profile by ID.
   * Access: Admin OR the user matching the {id} parameter.
   * Headers: Authorization: Bearer <token>
   * Response: 200 OK - User profile object | 403 Forbidden | 404 Not Found

3. POST /users
   * Description: Register a new user profile. Bypasses security checks for new accounts.
   * Payload: { "name": "...", "phone": "...", "email": "...", "role": "user" }
   * Response: 200 OK - Created user profile with a newly generated session JWT token.

4. PUT /users/{id}
   * Description: Overwrite / fully update user profile.
   * Access: Admin OR the user matching the {id} parameter.
   * Headers: Authorization: Bearer <token>
   * Payload: { "name": "...", "email": "...", "phone": "..." }
   * Response: 200 OK - Updated user profile with refreshed JWT token.

5. PATCH /users/{id}
   * Description: Partially update user profile (e.g. name, email, or avatar image).
   * Access: Admin OR the user matching the {id} parameter.
   * Headers: Authorization: Bearer <token>
   * Payload: { "image": "data:image/jpeg;base64,..." } OR { "name": "..." }
   * Response: 200 OK - Updated user profile with refreshed JWT token.

6. DELETE /users/{id}
   * Description: Permanently delete a user account from database.
   * Access: Admin OR the user matching the {id} parameter.
   * Headers: Authorization: Bearer <token>
   * Response: 204 No Content | 403 Forbidden | 404 Not Found
